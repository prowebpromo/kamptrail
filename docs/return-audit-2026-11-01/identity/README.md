# November 1, 2026 independent identity cross-check

The deployed 2.34.0 browser catalogue matched the deployed search index for all 33,370 canonical listings and all 36,290 distinct canonical and legacy IDs. Each listing's complete ID set matched. No listing was missing, unexpected or merged with another listing. This is the requested independent cross-check of the 2.33.0 identity behavior on the current release.

Two fresh 404 scenarios each loaded all states individually. Every time a state completed, the script compared every represented ID with its owner in the search index, and checked that previously shown marker IDs stayed present. Each run recorded zero wrong merges, zero unknown IDs and zero disappearing IDs. With the host file unavailable, 35,959 marker IDs appeared. 2,490 listings had multiple markers, and 26 listings appeared solely under another published ID. After unblocking the file and dispatching the browser's online event, the production reconnect listener fetched the hosts and rebuilt the catalogue. Every previously shown ID mapped to its original index listing via the published ID API and the restored listing's actual member set.

The request manifest records exact request targets, HTTP status, body length and SHA-256 for 133 TLS-verified public GET responses totaling 92,506,075 bytes. It includes all 50 merged state files and all 42 agency datasets published in the agency manifest. The public release response identifies source commit `a8785f981e58f745fbd57e34763b630ab73fe7d2`. The public search index SHA-256 was `83e6f21c026796ab6ee54f7963855d676536f29a5d95d256dadbbaf53b06c33a`. The client reported version 2.34.0. No production data or clients were modified by this audit.

## Method and evidence

1. `capture.py` fetches the real deployed page, assets, search index and datasets with ordinary TLS verification and computes the manifest. The fixtures are HTTP response bodies, independent of the repository files. Captured replay serves those bodies at their original HTTPS URLs in Chromium.
2. `census.cjs` opens a fresh browser context, lets the deployed application initialize at its normal map URL and calls its public state-loading API one state at a time. It obtains the index from the application's search-index API, independently constructs member→owner and canonical→all-members maps, and compares the actual browser features against them. Every required state and agency request is accounted for. Its rig check selects the actual map control, reads the resulting filter state and counts all loaded national records with the production filter function. The overview UI displays source totals rather than this national filtered count.
3. The direct HTTPS runs let Chromium fetch the page, its scripts and data through the workspace proxy. Fingerprints are compared with the TLS-verified public capture. Ancillary map imagery, the places directory and the service worker were excluded. Both profiles are Chromium, including mobile device emulation. These checks do not measure physical-phone offline behavior, popup rendering, historical saved records or production database content.
4. The original direct mobile raw log (`mobile-reverse-published.json`) contains 49 instrumentation errors for merged state files served by the host as `text/plain` with no charset. The DevTools `response.body()` interface serialized these files through Windows-1252. A direct spot check of the page's native `Response.arrayBuffer()` for Wyoming returned the full 994,950 bytes and the exact SHA-256 recorded in the capture. `verify-charset.cjs` reproduced all 49 DevTools SHA-256 values from the independently downloaded original bytes. `mobile-reverse-charset.json` contains the matched pairs. The other 81 browser resource hashes passed directly. All original listing assertions passed. The subsequent desktop direct run separately hashed all 97 required original validated responses in browser Cache Storage. All 97 SHA-256 values matched the independent capture.

Raw scenario JSON includes the state order, observed counts, controls, mismatch categories and request paths. For 404 runs, see each state's wrong-merge, unknown-ID and disappearance counts and the final reconstruction checks. The repository's existing acceptance scripts were not invoked or imported.
